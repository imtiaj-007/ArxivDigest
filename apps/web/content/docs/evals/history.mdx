<Callout type="info" title="How this page is populated">
  Each `arxivdigest eval` run appends a one-line JSON summary to
  `evals/metrics/history.jsonl` (see [`cli/commands/eval.py`](https://github.com/imtiaj-007/ArxivDigest/blob/main/apps/agent/src/arxivdigest/cli/commands/eval.py)).
  This page reads that file at build time. The daily cron's final step
  commits the new line back to `main` (with `[skip ci]`) so each cron run
  shows up here after the next Vercel build — usually within a minute.
  Local runs need to be committed manually to land on the deployed page.
</Callout>

## Reading the columns

| Column | What |
|---|---|
| **When** | UTC timestamp the run finished (ISO-8601, minute precision) |
| **Micro F1** | Pooled (paper, theme) agreement with ground truth — green ≥ 0.80 |
| **Macro F1** | Per-theme F1 averaged — green ≥ 0.80 |
| **Schema** | Fraction of LLM calls that parsed into Pydantic first try — green ≥ 0.95 |
| **Kw cov** | Avg fraction of expected-keyword strings present in stored summaries — green ≥ 0.65 |
| **Papers** | `processed/total` — anything less than total means an LLM call bulkheaded |
| **Commit** | Git SHA the eval ran against (links to GitHub if present) |

Click any column header to sort. Newest-first is the default. The chevron
at the start of each row expands the **per-theme F1 breakdown** for that
run (green ≥ 0.85, amber &lt; 0.75) — populated for runs from
2026-06-06 onwards; older rows show a "not recorded" message.

The sparkline above the table tracks micro + macro F1 across all runs
(oldest → newest); the dashed line is the 0.80 floor enforced by
`--fail-on-regression` in CI.

## What this isn't (yet)

- **Statistical change-point detection** — the sparkline above is a visual
  cue, not a regression test. The `--fail-on-regression` baseline gate in
  `daily-digest.yml` is the actual contract.
